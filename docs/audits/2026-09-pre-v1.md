## Reporting rules

A source observation is not a successful runtime test. A passing focused test is
not delivery. Final evidence must identify the tested commit and completed local,
PR and main gates. Critical/high confirmed findings must be resolved before 025
is delivered; other findings need explicit disposition. Historical MVCC/WAL and
host snapshots are outside a claim of absence from current logical records and
application-managed files; document their operational retention separately.

## A43 — tail-feature convergence: partial database rows, source ancestors and YAML

The independent tail review of integrated commit `bed463bdf` found three
bounded defects. Partial database projection merging appended local rows that
were not selected by the server page, which could exceed its limit or violate
the server filter/order. Directory import checked containment and the final
file handle but not the identity of intermediate ancestors across the read.
Frontmatter YAML had byte and alias limits but no semantic depth or node-count
limit.

The minimal corrections are recorded in 026 T022 and 028 T022. The database
merge now overlays only IDs selected by the server; source reads compare root
and ancestor `lstat` identities before and after each file; YAML rejects more
than 64 semantic levels or 100,000 AST nodes before conversion. Focused RED
tests failed before each implementation and GREEN tests pass afterward,
including normal exports, symlink/containment/mtime/size races and optimistic
pending/conflict overlays. The ancestor check is portable replacement
detection, not an OS-level lock against an attacker that restores identical
identities between checks. Complete local/PR/main delivery remains T040/T041.

## A44 — MCP refused credentials absent from the security audit

revoked credentials, but the refusal was only translated into the HTTP response.
No `security_audit_events` row existed for the attempt, leaving connection

response. Focused regression, API type and formatting validation pass. The
combined local/PR/main delivery gate remains pending under feature 013 T016.

## A46 — rollback leaves encrypted chunks outside the cleanup inventory

`ProtectedFileService` physically publishes encrypted chunk blobs before the
transaction writes their canonical chunk and manifest rows. A rejected
placement, failed protected-content publication, SQL error, or process crash
after publication can therefore leave an encrypted blob with no row for
`protected-file-cleanup` to discover. The old cleanup path only handled keys
queued when an already-known upload or rotated chunk was retired.

T061 registers each opaque storage key in the existing bounded
`protected_file_garbage` ledger immediately before the physical write, using a
short independent transaction. The canonical transaction acknowledges the key
after its chunk and manifest rows are durable. Cleanup runs under the existing
exclusive FILE maintenance lock, checks all canonical references before
deletion, and retires stale ledger rows even when the blob became canonical in
another operation. No unbounded filesystem scan or identity change is added.
The real rollback regression fails before the correction and passes after it;
focused API/type/Biome evidence is recorded in [T061 validation](../../specs/025-storage-coherence-audit/validation.md#t061--rollback-safe-protected-ciphertext-cleanup).
