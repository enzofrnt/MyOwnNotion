# Validation quickstart — Notion API

Use [the owner CLI guide](../../docs/notion-import.md) for integration access,
discovery, explicit selection, preview, apply and durable resume. The target
must be an independent Compose project with separate ports, volumes, checkout
and deployment key. Never run the default stack reset for this validation.

Synthetic fixtures cover paginated objects and properties, distinct sources,
same-title entries, native rich content, typed values, views, relations and
bounded media access. Canonical integration tests cover normal readback,
encrypted originals/snapshots, verified backup, interruption, restart/replay and
preservation of later edits. Existing source switching contracts remain gates
for the required core repair.
The owner corrections also test ignored people/authorship fields, excluded
covers from fresh and historical collections, private recovery originals,
inline database activation, keyboard editing and checkpoint reopen. Browser
inspection uses the isolated live instance, both themes and 320/1440 px;
temporary QA pages are trashed through canonical commands after verification.

See [validation-api.md](validation-api.md) for current evidence. The prior
[validation.md](validation.md) describes the retired file importer and is
historical. Real source evidence is recorded as aggregates only; secrets,
private titles and content never enter committed fixtures or screenshots.
