# Specification quality checklist

- [x] User needs and priorities are explicit and independently testable.
- [x] Product canvas, dependencies and exclusions are recorded.
- [x] Requirements avoid editor/library implementation choices.
- [x] Acceptance covers empty, invalid, populated, loading/error inherited states.
- [x] Offline data, export, privacy and existing owner edits are explicit.
- [x] Keyboard, themes, 320 px and visual evidence are required.
- [x] No material ambiguity requires owner input before planning.
